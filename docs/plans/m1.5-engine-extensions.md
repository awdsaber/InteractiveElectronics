# M1.5 — Engine extensions (triaged from the curriculum SIM NOTEs)

Sources: the "Engine features needed" list in `docs/curriculum/README.md`, and the SIM NOTE / Behaviors sections of each `docs/curriculum/T4..T7/*.md`. This plan takes what the lessons truly need. Where a cheaper model teaches the same lesson, use it.

Ruling: we model at the level that teaches the concept. Driver ICs, sensors and buses are Behaviors, not transistor-level models. Cost if wrong: some failure modes are less physical.

## Global constraints
Same as M1 (`docs/plans/m1-engine.md`). Also:
- Keep the existing `types.ts` fields backward compatible.
- Every new element and device needs a test with a hand-calculated value.
- Don't regress `src/engine/sim/perf.test.ts`.

## X1 — Simulator (`src/engine/sim/`)
1. **Waveforms on `V`:**
   - `wave?: { kind:'sine'|'square'|'triangle'; amp; freq; offset?; phase?; duty? }`.
   - In DC, use the value at t=0. In transient, evaluate at t.
2. **Supply current limit on `V`** (`iLimit?`, constant-current foldback), plus a `sink?: false` option that refuses back-fed current.
3. **Integration:**
   - Choosing a method: `Lesson.sim?: { dt?: number; method?: 'be'|'trap'; stepsPerFrame?: number }`. Trapezoidal must not damp LC ringing.
   - Slow-motion and time-lapse: the store handles time scaling, and the engine supports any dt.
4. **Breakdown clamps:**
   - `SW` and transistors get `vBreak?`, an avalanche clamp, so inductive kicks read realistic tens or hundreds of volts.
   - `ZENER` gets dynamic resistance `rz` with a soft knee.
5. **New elements:**
   - `POT` (3 terminals, `value` total Ω, `pos` 0..1).
   - `XFMR`: an ideal transformer (ratio `n`) with magnetizing inductance `lm`.
   - `LOGIC`: `{gate:'NOT'|'AND'|'OR'|'NAND'|'NOR'|'XOR'|'BUF'|'SCHMITT', inputs, out, vcc, vth?, hyst?}`. The output is a source behind 25 Ω. Inputs are high-impedance with thresholds. `SCHMITT` has hysteresis.
   - `FUSE`: an I²t blow curve.
   - `REG`: an LDO with `vout`, `dropout`, `iLimit`, `iq` and thermal shutdown through the thermal model.
6. **Thermal model for ratings:**
   - Rating fields: `rth?` (°C/W), `tauTh?` (s) and `tMax?` (°C).
   - When these are present, temperature decides burns instead of the 300 ms rule.
   - Publish `extra[id+'.tj']`.
   - Add `failMode:'shutdown'`, which disables the part until it cools.
   - Add `rmsWindow`, for pulsed and AC current.
7. **Ratings and patching:**
   - Check `maxI` on `SW`.
   - `applyPatches` 'set' supports nested keys (`rating.maxP`).
   - Electrolytic capacitors get a reverse-voltage rating (`polarized: true`, which fails with a short on reverse voltage).
8. **PIN extensions:**
   - `vccNode?`: HIGH follows the rail.
   - `openDrain` mode.
   - `adcBits` and `pwmFreq` come per board from the Sketch.
9. **Initial state:** `C.v0` already exists. Add `ic?: Record<NodeId, number>` for a transient initial guess, so latches power up deterministically.

## X2 — Virtual MCU (`src/engine/mcu/`)
1. **Interrupts:**
   - `attachInterrupt(digitalPinToInterrupt(p), isr, RISING|FALLING|CHANGE)`, `detachInterrupt`, `noInterrupts`/`interrupts`, `volatile`, and function names as values.
   - ISRs run synchronously, preempting the main code at statement boundaries.
2. **Timestamped edges:**
   - `VirtualMcu.injectEdge(pin, level, tMicros)` for behaviors.
   - µs-precision `delayMicroseconds` and `micros`.
   - `pulseIn(pin, level, timeout)`.
   - `digitalRead` inside an ISR returns the level at the edge.
3. **Per-board semantics:**
   - Uno: 16-bit `int` wraps, a 10-bit ADC and `analogReference`.
   - ESP32-S3: 32-bit `int` and a 12-bit ADC with analog pins keyed by GPIO.
4. **Libraries and built-ins:**
   - `tone`/`noTone`.
   - `bitWrite`/`bitSet`/`bitClear` (rewritten as assignments).
   - `String.toInt`/`toFloat`/`toUpperCase`/`indexOf`/`substring`.
   - `Serial.read`/`available` with input from the UI serial box.
   - `Wire` master API and `SPI`/`SPISettings`, both delegating to bus behaviors.
   - Constructing behavior classes, e.g. `Adafruit_PWMServoDriver pwm = Adafruit_PWMServoDriver(0x40);`.

## X3 — Behavior framework (`src/engine/behaviors/`)
1. Change `Lesson.behaviors` to `Array<string | { id: string; instance?: string; params?: Record<string, number|string|boolean> }>`.
2. Extend `BehaviorContext` with:
   - `params`
   - `netlist` (read-only, patched)
   - `v(node, ref?)`
   - `isFloating(node)`
   - `mcu: { hold(reason), release(), reset(), injectEdge(...), serialIn(str) }`
   - `burn(elementId, reason)`
   - `addElement` / `removeElement`
   - `events.push({t, channel, kind, data})`, for logic-analyzer and scope timelines
   - `setMotorLoad(elementId, torque)`
3. Tweaks and patches can target `behavior:<instance>.<param>`.
4. Shared behaviors to build first:
   - `mcu-supply`: brown-out reset.
   - `serial-plotter`: `serial.<name>` readouts.
   - `sine-source`, if not covered by X1.1.
   - `bounce`: contact bounce.
   - `logic-analyzer`: an event recorder plus UART/I²C/SPI decode.
5. Lesson-specific behaviors are written with their lessons in M2–M4. The full list is in the curriculum files.

## X4 — UI and bench
1. **Multiple power sources:** `Lesson.powerElementIds?: string[]`, with one power button per source, labelled.
2. **Tweak types:** `kind?: 'slider'|'enum'|'momentary'|'toggle'`, plus `link?` for ganged pots or switches.
3. **Readout units and kinds:**
   - Units: '%', 's', 'counts', 'µs', 'mΩ', 'dBm', 'C'.
   - `derived` readouts: sum or ratio of other readouts.
   - A `chart` readout: a strip chart of N signals.
4. **Instrument panel (toggleable):**
   - A 2-channel scope with time/div, V/div and an edge trigger.
   - A logic-analyzer timeline built from behavior events.
   - Both sample from the sim at dt, not at the frame rate.
5. **Sim speed control:** ×0.01 slow-motion up to ×100 time-lapse.

## X5 — 3D part additions
- Packages: SOT-23, 0402/0603 chips, TQFP-32/44, Multiwatt15, fiducial and mounting hole.
- Large and moving parts: a chassis, a tilt plate (draggable) and servo horns driven by angle.
- Mechanics: the gear output wheel uses the `gear` param.
- Solder joints: fillet variants for good / cold / bridged / insufficient.
- A PCB layer-tour mode: copper, mask, silk and drill layers peeled apart.

Order: X1 and X2 run in parallel (separate dirs), then X3 (it touches the store), then X4 and X5 in parallel.
